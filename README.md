# reminders

The Reminders example of [apple-apps](https://github.com/coenttb/apple-apps): an independent, offline SwiftUI reference application for modern Apple application practice, targeting iOS 27. It is the [SQLiteData Reminders example](https://github.com/pointfreeco/sqlite-data/tree/main/Examples/Reminders) reworked domain-first, with the chrome of the iOS 27 Reminders app.

Two Swift packages. The **core** package at the root (`reminders`: `Reminders`, `Reminders SQLiteData`, `Reminders Feature`) is platform-free: the pure **domain**, its SQLite **stored form** (`Reminders SQLiteData`: records, migration, load/seed/persist mapping), and the TCA26 **feature** that owns the domain value over it; it imports no SwiftUI, SwiftData, UIKit, or AppKit. It adds `swift-tagged` and enables the `Tagged` trait of `sqlite-data`, so `Reminder.ID`, `Reminder.List.ID`, `Tag.ID`, and `Lists.Detail.ID` are columns. The **Apple** package at `reminders-apple/` (`Reminders View`, `Reminders App`) holds the SwiftUI **view** layer and the thin **application** layer (`Reminders App`: the root screen over the store and the live store factory). Server, web, and Android layers will be further sibling packages here, each depending on the core and never the reverse. Every target has one `<Target> Tests` target. `reminders-apple/Reminders.xcodeproj` holds the one host application, `App.swift` and `App.xcconfig` under `reminders-apple/Hosts/Reminders/`, whose source does nothing but create the live store and show `Root` (bundle identifier `com.coenttb.apple-apps.reminders`, module `Reminders_Host`). Conventions shared by every example (naming, layering, the owner, what `Accessory` provides) are described in the umbrella's README. The example's own research record is [RESEARCH.md](RESEARCH.md); captures and the static review are under [Evidence/](Evidence/).

| Local controls | Native host |
| --- | --- |
| iOS 27 chrome: solid stat tiles, lists, tags, search from the bottom bar with `#tag` tokens, complete with a five-second undo, order and show-completed per detail, reminders edited in place in a list (a raised row with Date, Time, Repeat, and Location chip menus, Return chaining a new row beneath), reminder and list sheets with a coupled Date and Time pair and a discard confirmation, seed data (Debug) | Native `List`, `searchable(text:tokens:)` with `searchToolbarBehavior(.minimize)` and `DefaultToolbarItem(kind: .search, placement: .bottomBar)`, `glassProminent` New Reminder in the bottom bar, `navigationDestination(item:)`, `interactiveDismissDisabled` with a discard popover anchored to the X |

Reminders keeps the whole graph (lists, reminders, tags, per-detail ordering and show-completed, and the open detail) in SQLite and restores it on relaunch; a reminder's due date carries a separate `hasTime` flag, as a date without a time is its own state in the stock app.

## Build

Open `reminders.xcworkspace`. Its shared scheme `reminders.xcworkspace`, named after the workspace file, builds every target of the two packages and the host and runs the test targets; the host scheme `Reminders` runs the app on a device or simulator. Scheme autocreation is off, so package targets get no schemes of their own. The packages target iOS only, so they build through the workspace, not with `swift build` on macOS.

```sh
xcodebuild -workspace reminders.xcworkspace -scheme reminders.xcworkspace -configuration Debug \
  -destination "platform=iOS Simulator,id=$(Tools/simulator.sh create)" build-for-testing
```

This example is one unit of work: a lane opens this workspace, and no other, and works on a simulator of its own. `Tools/simulator.sh create` creates and boots `iPhone 17e · reminders` (pass another device type as the second argument), `udid` prints it, `delete` removes it; never install on, drive, or reset a simulator you did not create. Xcode keys its derived data by workspace path, so lanes on different examples share no build state; do not pass a shared `-derivedDataPath`. `Tools/generate_project.py` regenerates the host, the project, the host scheme, and this workspace after a package target changes (deterministic, byte-identical on re-run).

Dependencies are declared by URL only, never by path: `reminders-apple` depends on `https://github.com/coenttb/reminders` and `https://github.com/coenttb/accessory`, and both packages on `https://github.com/pointfreeco/TCA26.git` (traits `Dependencies` and `Clocks`). The workspace resolves each URL to a local checkout by referencing it: the two packages here, the sibling `../accessory` checkout, and the `pointfreeco/TCA26` checkout (`../../pointfreeco/TCA26` beside a standalone checkout, `../../../pointfreeco/TCA26` inside the `apple-apps` umbrella; the generator probes both). Without a sibling checkout the URL is fetched instead.

For a layout baseline, add `-plain-surfaces` to a scheme's Run arguments. This replaces custom glass with a plain surface without changing the field's view structure. System tab bars and sheet materials remain system-rendered. A connected hardware keyboard can hide the software keyboard: keyboard verification requires seeing the rendered keyboard, not merely a focused field.

## Module structure

`Lists` is the whole graph as one value: lists, reminders, tags, per-detail preferences, and the open detail. Everything the reference app expressed as SQL is a rule on that value: `Lists.Stats` counts the tiles, `Lists.reminders(in:at:)` filters a `Lists.Detail` (`.today`, `.scheduled`, `.all`, `.flagged`, `.completed`, `.list(id)`, `.tags([id])`) by membership and by its persisted `Preference` (ordering and show-completed) and sorts it, `Lists.matches(_:)` runs the search (`Lists.Search` holds the text and the committed `Token`s, `.near(String)` or `.tag(Tag.ID)`), and `toggle` starts the five-second grace period (`Reminder.Status.completing`) that `completeCompleting()` ends. A completing reminder counts as completed everywhere except that it stays on screen so the tap can be undone. Moving a reminder switches its detail to manual ordering. Identifiers are `Tagged` (`Reminder.ID`, `Reminder.List.ID`, `Tag.ID`, `Lists.Detail.ID`).

`Lists.View` is the home (stats, lists, tags), `Lists.Detail.View` a detail with its ordering and show-completed menu, `Lists.Search.View` the results with the completed counter and its clear menu, `Reminder.Form` and `Reminder.List.Form` the sheets, `Tag.Picker` the tag popover; each takes the value and one callback per intent. The row intents (complete, delete, details, and edit where rows edit in place) travel as one `Reminder.Row.Actions` value and the inline card's (complete, details, submit, the Date and Time chips) as one `Reminder.Editor.Actions`, built once in the application layer; the chips are intents rather than binding writes because they run calendar rules on the feature's clock. `Lists.Feature` delegates every action to the domain, persists on change (only rows that differ from the stored value are written, compared inside the same transaction), and runs the grace timer on the completing set (restarted by each tap, revived at mount if the app quit mid-period). The two forms are child features presented as one `Destination` (`Reminder.Feature` and `Reminder.List.Feature`, each owning its draft and whether it is new; Save and Cancel are decided by the parent, which reads the draft back and refuses a blank title); the sheets bind to `$store.scope(\.destination, action: \.destination).reminder` and `.list`. `Reminders App` hosts the navigation stack: the open detail is `navigationDestination(item: $store.lists.detail)`, so navigation is data and survives relaunch.

```swift
Lists.View(lists: store.lists, now: now, open: { store.send(.statTapped($0)) }, details: { store.send(.listDetailsButtonTapped($0)) },
           delete: { store.send(.listDeleted($0)) }, move: { store.send(.listsMoved($0, $1)) }, deleteTag: { store.send(.tagDeleted($0)) })
.navigationDestination(item: $store.lists.detail) { detail in Detail(detail, store: store) }
```

`Root.Detail` is the pushed screen: it holds the store and reads `store.lists` in its own body, then builds `Lists.Detail.View` from the value with one `Reminder.Row.Actions` and one `Reminder.Editor.Actions`. A value view built inside the `navigationDestination` closure would keep the lists it was first given.

Dropped from the reference on purpose: CloudKit sharing and sync, list cover images, the FTS5 trigram index with its highlighting and `NEAR` proximity, TipKit. Search matches title, notes, and tags case-insensitively in memory.
